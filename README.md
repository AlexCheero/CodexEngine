# CodexEngine

CodexEngine is the reusable C# runtime and Godot authoring layer used by Griefborn and CyberFPS. A game checks out this repository as its `Engine` submodule. Open `CodexEngine.sln` to work on runtime code independently, or open the consuming game's Godot C# solution to debug engine and game code together.

| Directory | Responsibility |
| --- | --- |
| `CodexECS` | Entity storage, filters, systems and the pipeline from the Unity project's ECS, plus jobs, command buffers and pipeline assets |
| `CodexNetworking` | Transport, serialization, snapshots and ECS synchronization |
| `Runtime` | Pure entity presets, math, Jolt simulation primitives and the shared scene and mesh formats |
| `Rendering` | FNA static and skinned mesh rendering, GPU assets, shader sources and FXC compilation |
| `Godot` | Editor-authored presets and components, content baking and integration with the consuming Godot project |
| `ThirdParty` | FNA framework sources and native libraries, plus BRUTAL notices and attribution |
| `Tools` | Installation and configuration of the pinned Godot .NET and .NET SDK toolchain |

The runtime consumes the Ahwoo BRUTAL Jolt package pinned in `Runtime/CodexEngine.Runtime.csproj`. The ECS and networking directories contain the C# versions ported from the Unity game. Their upstream repositories are [Codex ECS](https://github.com/AlexCheero/ECS) and [CodexNetworking](https://github.com/AlexCheero/CodexNetworking).

`DirectionalShadowMap` takes a direction toward the sun, a texture resolution, a coverage radius and a light-space depth on either side of the centre, in world units. It can hold up to four nested cascades in one atlas, each a third as wide as the next, and filters with 4, 9 or 16 comparisons. Call `Position(eye, forward)` before collecting casters. On culling workers, use `Reaches` to find what can cast at all, independently of camera visibility. Call `Begin`, then for each cascade call `BeginCascade`, draw the casters that pass `Intersects` and render from `ViewProjection` using the stock `StaticShadow` and `AnimatedShadow` techniques or your own depth-writing material. `Intersects` leaves out a caster that a smaller cascade holds whole, so most casters are drawn once. Switch to the scene target and call `BindReceiver(material, true)` before drawing lit surfaces. Custom effects can include `Rendering/Shaders/DirectionalShadows.hlsl` and multiply direct sunlight by `SunVisibility(worldPosition, worldNormal)`. The include reserves pixel sampler 1. It takes screen-space derivatives, so call it before the first branch of a pixel shader: with a branch ahead of it, flat ground shadowed itself.

A `[branch]` whose condition reads only uniforms is never taken on the SDL_GPU backend: FXC compiles it to a static branch on a bool register, and the code inside silently does not run. Wrap such a condition in `PER_PIXEL(condition, varying)` from `Rendering/Shaders/Branching.hlsl`, which ANDs in a per-pixel term and keeps the branch dynamic.

`Rendering/Shaders/LitSurface.hlsl` is the lit surface games share. `GatherLight` collects what reaches a surface (lightmap or light probes, the sun with its shadows, the level's local lights from a `LightGrid`) and `ShadeSurface` turns it into radiance (Lambert or URP Lit with sky reflections) under the level's fog. A game's effect supplies the vertex stage, the surface's colour and normal, and whatever light of its own it adds between the two calls. `GatherLight` also takes an occlusion factor for the ambient part and, in its longer form, the metalness at the texel, for an effect that reads Unity's occlusion and metallic maps. The header of the file lists the samplers it reserves and the C# class that binds each input.

`RenderQuality` holds what a quality tier costs the renderer: scene multisampling, edge smoothing, anisotropy, the largest surface map, ambient occlusion and the sun shadow settings. A tier smooths edges or multisamples, not both: the smoothing pass costs a textured wall about a tenth of its local contrast. `RenderQuality.Tier(index)` returns the four stock tiers and `SurfaceSampler` the tier's wrapping sampler. Bind that sampler from code and name no filter in the effect: FNA reapplies an effect's filter on every pass and reads an anisotropic one there as linear.

`UrpPostProcessing` applies a Unity URP volume stack to the HDR scene. `EdgeSmoothing` adds an FXAA pass over the graded frame, and `Dither` (on by default) adds one display step of noise so dark gradients show no bands in the 8-bit output. `OutsideAlpha` names the alpha of surfaces that stand outside the stack, for what Unity draws after post-processing (a held weapon): the frame shows them as lit, with no bloom, vignette, exposure or grade, and they cast no bloom. `Shafts`, set per frame, adds light shafts from the sun: the sky around it streaks past whatever stands in front. They read the scene's alpha to tell sky from surface, so the scene must keep 1 there for sky and less for anything drawn over it.

Depth kept in a colour target for later passes must put the sky at the far end of its range, as the scene's alpha and `ScreenSpaceAmbientOcclusion.SkyDepth` do. Marked with zero instead, the sky drags every silhouette toward the eye once filtering or a multisample resolve averages it with a real depth, and soft particles behind the silhouette fade out in a halo.

`TexturePreparation.Prepare` turns a PNG or JPEG into a `PreparedTexture` on an asset worker: it builds the smaller levels in linear light (decoded first for RGBM lightmaps) and stores power-of-two colour maps as BC7. It reads PNGs itself and keeps the colour they hold under zero alpha, which FNA's decoder blacks out: filtering blends that colour into every cutout's rim, and Unity's import keeps it too. With a cache directory it keeps the compressed result between runs, named by the source's name, size and write time. Call `Create` on the game thread to upload, with a size limit to leave a large map's finest levels out.

`EnvironmentCube.FromCross` builds the reflection cubemap from a horizontal-cross sky image: linear radiance in half floats, each smaller level convolved for a rougher surface. Sample it with `texCUBElod(cube, float4(reflection, UrpReflectionMip(brdf)))`. For a reflection probe, `EnvironmentCube.Capture` draws the scene around a point through a callback and returns its six faces; `Convolve` turns them into the cube's levels on any thread and `Create` uploads them, so a game can capture on a level's first frame and take the cube up a few frames later. The lit shader reads one cube per draw (`EnvironmentCube`): bind the probe's for draws inside its box and the sky's for the rest.

`Atmosphere` holds per-level fog settings for effects that include `Rendering/Shaders/Atmosphere.hlsl`: thinning with height, a share of the colour taken from the sky and a glow toward the sun, plus the strength of the light shafts. With no entry a level's fog stays as authored and it has no shafts. `Bind` takes the sky's colour along the six axes (`EnvironmentCube.Axes`) for that share; the fog does not read the reflection cube, which may be a probe's.

On Windows x64, build the engine with `dotnet build CodexEngine.sln -c Release` using .NET 10 and a Windows SDK with x64 FXC. The game’s `Edit.cmd` sets up the bundled tools, exposes the engine add-on directly to Godot and opens the editor. The asset files and gameplay components in a game determine what gets rendered or simulated.

`ScreenSpaceAmbientOcclusion` loads `AmbientOcclusion.fxb`. After drawing the sky, call `BeginOpaque(scene)` with a colour and depth target created with `PreserveContents`. A frame whose sky covers the whole target can instead call `BeginScene(scene)` first and draw the sky with the `SceneOnly` blend state: both targets then clear in one render pass, which matters on a multisampled scene because every target switch resolves all its samples. Stock lit materials write ambient RGB and axial view depth to the second colour attachment. Custom materials can use `WriteSurface` in `Rendering/Shaders/AmbientSurface.hlsl` for the same layout. After opaque geometry, call `Apply(projection, radius, strength)` with the active perspective projection and a radius in world units, or `EndOpaque()` on a frame without occlusion. Either restores the scene target for subsequent transparent draws, and from then on `Surfaces` is the frame's shared depth: what soft particles and decals read for the distance behind a pixel, in world units along the view axis, with `SkyDepth` where nothing was drawn. Reading it saves those passes a copy of the scene.

`IndirectLightBake.Write` bakes visible skylight and one diffuse bounce from textured static scene geometry. Supply the same sun direction and colours as the player, and the horizontal bounds where moving objects need probes. The resulting `.brgi` contains a world-space colour mesh and six directional irradiance values per probe. Load it with `BakedSceneLight.Read`. Use `StaticMeshRenderer.CreateBatch(light)` to draw the refined surface with vertex irradiance in `COLOR1`, and keep the original scene mesh for shadow casters. For moving objects, create `IrradianceProbes`, call `Bind(material)` and sample `ProbeIrradiance(worldPosition, unitNormal)` from `Rendering/Shaders/IrradianceProbes.hlsl`. It reserves pixel sampler 2 unless the effect defines `PROBE_SAMPLER` before the include. `IrradianceProbes.Read` loads a Unity scene's baked light probes from the `.lightprobes` file that `Tools/UnityFidelity` writes and resamples them onto a grid.


## Pipelines and jobs

A pipeline asset is a JSON file with one ordered list of systems per category (`Init`, `Update`, `LateUpdate`, `FixedUpdate`, `LateFixedUpdate`, `OnEnable`, `OnDisable`, `Reactive`), the same lists the Unity integration serializes. Each entry holds the system's full type name and its `Active` and `NonPausable` flags. `PipelineAsset.Load(path).Build(world)` creates every system through its constructor taking one `EcsWorld`, and `PipelineHost` ticks the categories. Systems reach shared objects with `world.Service<T>()`. Mark a system with `[System(ESystemCategory.FixedUpdate)]` to offer it in the editor.

`JobScheduler` runs single and batched jobs in dependency order. Give one to `EcsWorld.Jobs`; `RangeWorkers` exposes the scheduler it dispatches on. `filter.ScheduleParallel(body)` hands a body batches of pages to iterate. Jobs cannot change structure: they record into `world.CreateCommandBuffer()`, which plays back at the next sync point in an order that does not depend on thread assignment.

A system that declares nothing is a sync point: the pipeline finishes every job on component data and plays back every command buffer before it ticks. A system that calls `Declare().Read<T>().Write<T>()` in its constructor ticks beside jobs on other data. It schedules with its `Dependency`, stores the handle of what it scheduled back into it, and calls `CompleteDependency()` before touching declared components itself. Every group ends at a sync point. A job that touches no component data can be scheduled on the scheduler directly and completed by its owner.

`PhysicsStepSystem` and `BodySampleSystem` are the collision world as pipeline systems. A game adds a `PhysicsStepRequest` to an entity, lists both systems, and reads each entity's `BodySample` afterwards. They need the world's `CollisionWorld` service.

## Codex Editor

Run `Edit.cmd` on Windows to open the standalone Godot .NET authoring project. The launcher installs the pinned upstream Godot .NET distribution and builds the editor scripts. The Codex editor customization lives under `Godot/addons/codex_engine` and includes the Entity Presets dock, the component inspector, and the content baking tools.

Projects that embed the workbench enable `res://addons/codex_engine/plugin.cfg` in their Godot project and store their entity presets in `res://Entities`. A project can set `codex/editor/entity_palette` to its own C# script derived from `EntityWorkbenchPalette` to expose game-specific components.

The Pipeline dock edits pipeline assets. Pick a `*.pipeline.json`, then add, remove, reorder (buttons or drag), activate and deactivate systems per category, as in the Unity pipeline inspector. It looks for the files in the folder named by the `codex/editor/pipeline_directory` project setting, then `res://Pipelines`, then `Content/Pipelines` of the game the standalone editor sits in. The systems on offer come from `systems.json` in that folder, which the game writes from `SystemCatalog.ExportJson()`.
